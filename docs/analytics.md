# Реферальная воронка

Администратор получает отчёт по всем реферальным кодам через
`GET /api/v1/analytics/referrals`. В ответе только агрегаты. Владелец кода может
посмотреть свои показатели через `GET /api/v1/referrals/statistics`.

| Поле | Что измеряет | Время события |
| --- | --- | --- |
| `total_clicks` | Число записанных переходов | `referral_clicks.clicked_at` |
| `unique_visitors` | Число различных `visitor_id` среди этих переходов | `referral_clicks.clicked_at` |
| `referred_registrations` | Число регистраций с зафиксированной реферальной атрибуцией | `referral_attributions.attributed_at` |
| `conversion_rate` | Регистрации / уникальные посетители × 100, строка с двумя десятичными знаками, округление ROUND_HALF_UP | Обе выборки за указанный период |

Если посетителей нет, конверсия равна `null`. Регистрация может попасть в период,
даже если исходный клик был раньше. Поэтому конверсия за период может превышать 100%.

Границы `date_from` и `date_to` принимают дату и время с часовым поясом. Начало
включается, конец исключается. Любую границу можно опустить. Фильтры `campaign`,
`source` и `referral_code` задаются совместно, сравнение точное и чувствительно
к регистру. Для регистрации берутся значения атрибутированного клика.
История отключённых кодов входит в расчёт.

При `group_by=day|week|month` поле `periods` содержит интервалы с событиями в
порядке возрастания. Границы календарные, в UTC, неделя начинается в понедельник.
Без группировки `periods` пуст. Верхний уровень всегда показывает итоги за весь
выбранный диапазон. Посетитель, пришедший в разные дни или по разным кодам,
учитывается один раз в итоге и один раз в каждом соответствующем интервале.

## CRM-воронка

`GET /api/v1/analytics/funnel` показывает, сколько заявок дошло до квалификации
и конверсии в CRM. Администратор видит все заявки, менеджер — только назначенные
ему на момент запроса. Переназначение меняет область видимости и для прошлых периодов.

| Поле | Правило расчёта |
| --- | --- |
| `total_leads` | Число заявок с датой создания в диапазоне `[date_from, date_to)`. Каждый лид одного клиента учитывается отдельно. |
| `qualified_leads` | Из отобранных заявок — число имеющих `qualified_at` до верхней границы. Сюда входят и заявки, потерянные после квалификации. |
| `converted_leads` | Из тех же заявок — число имеющих `converted_at` до верхней границы. Источником служит переход CRM в статус `converted`. |
| `lead_conversion_rate` | `converted_leads / total_leads × 100`, десятичная строка с двумя знаками, округление `ROUND_HALF_UP`. При пустой выборке значение равно `null`. |

Границы необязательны, принимают время с часовым поясом и возвращаются в UTC.
Без `date_to` учитываются все сохранённые переходы выбранных заявок.
При `group_by=day|week|month` заявки разбиваются по **дате создания**, неделя
начинается в понедельник. Для всех групп действует общая верхняя граница отчёта.
Например, для январского отчёта заявка от 5 января с конверсией 20 января попадёт
в число конвертированных за группу 5 января. Конверсия 1 февраля в этот отчёт
не попадёт. Пустые группы пропускаются. Без группировки список `periods` пуст.

`source` сравнивается с источником самой CRM-заявки. Фильтры `campaign` и
`referral_code` используют атрибуцию, привязанную к заявке при создании.
Заявки без атрибуции входят в общий отчёт и могут отбираться по `source`.
Все заданные фильтры применяются совместно, строки сравниваются с учётом регистра.
