# CRM-заявки

## Модель данных

`leads` хранит заявку, её пользователя, источник, статус и необязательного
назначенного менеджера. Допустимые статусы: `new`, `contacted`, `qualified`,
`converted`, `lost`; начальный статус по умолчанию — `new`. Поля `created_at`,
`updated_at`, `qualified_at` и `converted_at` хранятся с часовым поясом;
время квалификации и конверсии может отсутствовать. Источник обязателен и не
может состоять только из пробельных символов.

Необязательная `referral_attribution_id` связывает заявку с атрибуцией того же
пользователя: это проверяется внешним ключом PostgreSQL. Заявку можно создать
без атрибуции. Связанные пользователь, атрибуция и назначенный пользователь не
могут быть удалены, пока на них ссылается заявка.

`lead_status_history` хранит предыдущий и новый статусы, пользователя-автора
и время изменения. Предыдущий статус может быть `null` для записи о создании;
одинаковые предыдущий и новый статусы запрещены. История ссылается на заявку и
автора без каскадного удаления. Индексы подготовлены для поиска заявок по клиенту,
статусу, менеджеру и времени, а также для чтения истории и поиска по атрибуции.

На уровне этой схемы внешний ключ менеджера проверяет существование пользователя,
но не его роль. Политика доступа, проверка роли менеджера, разрешённые переходы,
автоматическая запись истории и защита от повторной конверсии будут реализованы
в сервисном слое на следующих задачах. API заявок пока не добавлено.
