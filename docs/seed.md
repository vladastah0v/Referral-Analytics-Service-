# Синтетические данные

Команда `python -m scripts.seed` загружает в PostgreSQL синтетические данные для проверки реферальной аналитики. Выберите отдельную базу через `DATABASE_URL`: её отчёты будут учитывать созданные операции и регистрации. Перед первым запуском примените миграции.

```bash
uv run alembic upgrade head
uv run python -m scripts.seed --seed 42 --start-date 2025-01-01 --days 60
```

Для стенда в Docker Compose после сборки образа доступны те же команды.

```bash
docker compose run --rm api alembic upgrade head
docker compose run --rm api python -m scripts.seed --seed 42 --start-date 2025-01-01 --days 60
```

| Параметр | Значение по умолчанию |
| --- | --- |
| `--seed` | 42 |
| `--start-date`, `--days` | 60 суток с 1 января 2025 года, начиная с 00:00 UTC |
| `--users` | 10 000, включая 40 рефереров и 6 менеджеров |
| `--clicks` | Три перехода на пользователя, всего 30 000 |
| `--referrals` | Пятая часть числа пользователей, в пределах количества переходов. По умолчанию 2 000 |
| `--leads`, `--orders` | По половине числа пользователей, по умолчанию по 5 000 |

Малый набор можно создать отдельной командой.

```bash
uv run python -m scripts.seed --seed 7 --users 200 --clicks 600 --referrals 40 --leads 100 --orders 80 --days 30
```

Для каждой атрибутированной регистрации есть реферер, его код и переход за предшествующие 30 дней. Остальные переходы включают повторные посещения. Параметр `campaign` распределяет переходы между четырьмя кампаниями. Заявки и заказы появляются после регистрации и получают атрибуцию клиента. История заявки начинается с её создания и содержит переходы до сохранённого статуса. Сгенерированные учётные записи не имеют пароля для входа.

Источник заказов — `synthetic-<seed>`. Все заказы начинаются в статусе `created`. Программа с вознаграждением 5% в KZT действует в течение выбранного интервала. Выручка и начисления появятся после обработки финансовых событий.

Весь набор записывается одной транзакцией. При успешной загрузке команда печатает JSON со статусом `created`. Повтор с тем же seed и параметрами возвращает `already_exists`, в том числе при параллельном запуске. Если объём или период изменились, используйте другой seed. Ошибка при вставке откатывает загрузку целиком. Фиксированные параметры воспроизводят те же идентификаторы, связи, даты и суммы на другой чистой базе.

## Оплаты и возвраты

После загрузки набора запустите API, Celery worker и beat для той же базы. Для набора с seed 42 один раз создайте ключ источника в интерактивном терминале.

```bash
uv run python -m app.cli create-integration --source synthetic-42
```

Передайте выданное значение через переменную окружения `INTEGRATION_KEY`. Генератор использует `DATABASE_URL` для чтения заказов и отправляет операции в API. По умолчанию он обращается к `http://127.0.0.1:8000` и отправляет до 100 событий за запрос.

```bash
uv run python -m scripts.generate_events --seed 42 --batch-size 100
```

Каждый заказ получает полную оплату через секунду после создания. UUID заказа определяет группу возврата: примерно у 10% заказов возвращается вся сумма, ещё у 10% — половина с округлением до тиына. Возврат происходит через секунду после оплаты. Все суммы и даты воспроизводятся из исходных заказов и попадают в период набора.

В результате отправки `accepted` показывает число новых событий, а `replayed` — число ранее принятых. При обрыве соединения повторите команду с тем же seed. Идентификаторы событий и финансовых операций сохраняются и при изменении размера пакета. Если API сообщает об отклонённом событии, причину и порядок повторной обработки можно найти в [документации интеграционных событий](tracking.md).

После обработки очереди выполните сверку. Для неё достаточно подключения к базе.

```bash
uv run python -m scripts.generate_events --seed 42 --verify
```

Команда проверяет события, операции и текущее вознаграждение по каждому заказу выбранного источника. При незавершённой обработке или расхождении она выводит причину и завершается с ненулевым кодом. Успешная сверка выводит суммы оплат, возвратов, чистой и атрибутированной выручки, а также вознаграждений в KZT. Для исходной программы ожидаемое вознаграждение равно 5% от остатка каждого атрибутированного заказа с округлением до тиына. Выручка относится к дате операции, история вознаграждений — к дате фактического начисления.

Для запуска внутри контейнера API используйте те же параметры. Если генератор запущен в отдельном контейнере Compose, укажите адрес сервиса через `--api-url http://api:8000`.

```bash
docker compose run --rm -e INTEGRATION_KEY api python -m scripts.generate_events --seed 42 --api-url http://api:8000
docker compose run --rm api python -m scripts.generate_events --seed 42 --verify
```
