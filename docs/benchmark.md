# Нагрузочное тестирование

Запуск рассчитан на отдельный синтетический стенд. PostgreSQL должен загружать `pg_stat_statements`, а Redis для кэша должен работать отдельным экземпляром от брокера и хранилища результатов Celery. Redis ведёт счётчики попаданий на весь экземпляр, включая все его логические базы.

## Подготовка стенда

```bash
docker run -d --rm --name referral-bench-pg -p 127.0.0.1:59451:5432 \
  -e POSTGRES_USER=bench -e POSTGRES_PASSWORD=bench-local -e POSTGRES_DB=referral_bench \
  postgres:16 -c shared_preload_libraries=pg_stat_statements
docker run -d --rm --name referral-bench-cache -p 127.0.0.1:59452:6379 redis:7
docker run -d --rm --name referral-bench-broker -p 127.0.0.1:59453:6379 redis:7
```

После готовности PostgreSQL создайте расширение и загрузите исходный набор.

```bash
docker exec referral-bench-pg psql -U bench -d referral_bench -v ON_ERROR_STOP=1 \
  -c 'CREATE EXTENSION pg_stat_statements'

export APP_ENV=test
export DATABASE_URL=postgresql+asyncpg://bench:bench-local@127.0.0.1:59451/referral_bench
export REDIS_URL=redis://127.0.0.1:59452/0
export CELERY_BROKER_URL=redis://127.0.0.1:59453/1
export CELERY_RESULT_BACKEND=redis://127.0.0.1:59453/2
export ANALYTICS_CACHE_TTL_SECONDS=60
uv sync --locked --group performance
uv run alembic upgrade head
uv run python -m scripts.seed --seed 42 --start-date 2025-01-01 --days 60
```

В отдельных терминалах с теми же переменными окружения запустите три процесса.

```bash
uv run uvicorn app.main:app --host 127.0.0.1 --port 59454
uv run celery -A app.workers.celery_app:celery_app worker --concurrency=2 --loglevel=INFO
uv run celery -A app.workers.celery_app:celery_app beat --schedule=/tmp/referral-benchmark-beat
```

В новом терминале с тем же окружением выполните запрос готовности и запустите тест с новым каталогом результатов.

```bash
curl --fail http://127.0.0.1:59454/health/ready
uv run --locked --group performance python -m scripts.benchmark \
  --host http://127.0.0.1:59454 --output /tmp/referral-benchmark-run \
  --seed 42 --users 8 --spawn-rate 4 --seconds 30
```

Прогон использует временные сеансы для чтения статистики и отчёта, а также ключ нового источника для записи событий. Скрипт удаляет временные учётные данные по завершении. Операции остаются в базе, поэтому для сравнения результатов между прогонами заново поднимите пустой стенд и загрузите тот же seed. После прогона остановите процессы API и Celery, затем остановите три контейнера командой `docker stop referral-bench-pg referral-bench-cache referral-bench-broker`.

## Сценарии и метрики

Фаза `read` поровну распределяет запросы между статистикой реферера и общим отчётом. Фаза `mixed` добавляет регистрацию переходов, пакеты из десяти подтверждений перехода и пакеты из трёх событий заказа. В пакет заказа входят создание, оплата и повтор той же операции с другим идентификатором доставки. Сценарий использует штатное расписание Celery beat и ожидает обработки очереди после смешанной фазы. Сверка проверяет, что у каждого заказа одна оплата на 100 KZT и одно вознаграждение на 5 KZT.

Locust записывает RPS, среднее время ответа, p50, p95, p99 и число ошибок в CSV. Ошибка любого элемента пакета считается ошибкой HTTP-запроса в статистике Locust. HTTP-время для пакета измеряется до ответа о приёме. Обработка начислений проверяется отдельно после остановки HTTP-нагрузки. Для настройки headless-режима см. [документацию Locust](https://docs.locust.io/en/stable/configuration.html).

В `summary.json` время PostgreSQL — разность `total_exec_time` в `pg_stat_statements` за фазу, включая запросы API и фоновых задач к тестовой базе. Среднее делит это время на число вызовов SQL. Доля попаданий Redis вычисляется по разностям `keyspace_hits` и `keyspace_misses`. Изменение данных обновляет версию кэша, поэтому фаза чтения и смешанный профиль измеряются отдельно. Скрипт завершится с ненулевым кодом при ошибках Locust, необработанных событиях или расхождении начислений. По умолчанию на разбор остатка очереди выделено до 180 секунд после HTTP-фазы.

## Замер 20 ноября 2026 года

Исторический замер использовал дополнительные параллельные задачи outbox во время смешанной фазы и ожидания очереди. Текущая команда работает со штатным расписанием и сохраняет временной бюджет outbox в отчёте. Для сравнения этих режимов нужен новый замер на одинаковой конфигурации.

Синтетический набор с seed 42 содержал 10 000 пользователей, 30 000 переходов, 2 000 атрибуций, 5 000 заявок и 5 000 заказов в состоянии `created`. Исторический период — 60 суток с 1 января 2025 года. Фазы длились по 30 секунд с подъёмом до 8 виртуальных пользователей со скоростью 4 пользователя в секунду и паузой 0,35–0,7 секунды между заданиями. API, Locust и Celery работали на одном Mac с Intel Core i5-3210M и 16 ГБ ОЗУ. Docker выделял 2 CPU и около 5,76 ГиБ памяти. Использовались один процесс Uvicorn, два процесса Celery, PostgreSQL 16.16, Redis 7.4.12, Python 3.12.16 и Locust 2.47.0. TTL кэша составлял 60 секунд.

Смешанная фаза записала 91 переход и приняла 463 события в 89 пакетах. Сверка подтвердила одну оплату и одно начисление по каждому из 61 заказа, включая повторные доставки. Через 4,12 секунды после завершения HTTP-фазы в очереди источника было 0 ожидающих и 0 отклонённых событий. RPS относится к указанному профилю и числу виртуальных пользователей.
