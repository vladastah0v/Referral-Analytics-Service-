# Пользователи и авторизация

Публичные методы доступны по префиксу `/api/v1`. `POST /auth/register` принимает
`email`, `full_name`, `password` и создаёт только пользователя с ролью `customer`.
Пароль должен содержать от 12 до 128 символов. Адрес приводится к нижнему регистру;
одно и то же значение нельзя зарегистрировать повторно. Дополнительные поля, в том
числе `role`, запрещены.

`POST /auth/login` принимает `email` и `password` и возвращает `access_token`,
`refresh_token`, `token_type` и срок действия access-токена в секундах. Для
защищённых запросов, включая `GET /users/me`, используется заголовок
`Authorization: Bearer <access_token>`.

`POST /auth/refresh` принимает JSON `{"refresh_token": "…"}`, выдаёт новую пару
токенов и одновременно отзывает предыдущий refresh-токен. При конкурентных
запросах с одним токеном успешно выполнится только один. Повторное использование
старого токена вернёт 401, не отзывая уже выданную пару. `POST /auth/logout`
принимает действующий refresh-токен в том же формате и отзывает его сессию;
access-токены этой сессии немедленно перестают проходить проверку. При ошибке
аутентификации методы возвращают 401; при недостаточной роли — 403.

Пароли хранятся в виде Argon2id-хешей, refresh-токены — в виде SHA-256-хешей.
Случайный идентификатор в каждом refresh-токене обеспечивает высокую энтропию.
Сессия хранится отдельно для каждого входа. При обновлении её срок продлевается;
время жизни access- и refresh-токенов задают `JWT_ACCESS_TTL_MINUTES` и
`JWT_REFRESH_TTL_DAYS`. Публичной выдачи ролей `manager` и `admin` нет.

Для создания администратора выполните миграции и запустите команду в защищённом
интерактивном терминале с доступом к приложению и базе данных:

```bash
docker compose exec api python -m app.cli create-admin --email admin@example.com --full-name "Administrator"
```

Пароль запрашивается дважды без отображения на экране; передача пароля в аргументах
команды и неинтерактивное создание не поддерживаются. Доступ к контейнеру и базе
следует ограничивать администраторам инфраструктуры.

Для развёртывания задайте собственный случайный `JWT_SECRET` длиной не менее 32
байт и храните его вне репозитория. При `APP_ENV=production` значение для локальной
разработки отклоняется. Замена ключа отзывает все ранее выданные токены. Внешний
доступ к API должен использовать HTTPS.

Команда применения миграций:

```bash
docker compose exec api alembic upgrade head
```

Для интеграционных тестов нужна отдельная одноразовая база PostgreSQL с именем,
начинающимся с `test_`. Тесты применяют миграции и очищают таблицы пользователей
и сессий перед каждым сценарием и после него. Укажите адрес этой базы в
`TEST_DATABASE_URL`, затем запустите `uv run pytest`. Без переменной интеграционные
тесты пропускаются.

Пример запуска отдельной тестовой базы и тестов:

```bash
docker run --rm -d --name referral-auth-test-db \
  -e POSTGRES_USER=test_user -e POSTGRES_PASSWORD=test_password \
  -e POSTGRES_DB=test_referral_analytics -p 127.0.0.1:55432:5432 postgres:16
# Дождитесь готовности PostgreSQL, затем выполните:
TEST_DATABASE_URL=postgresql+asyncpg://test_user:test_password@127.0.0.1:55432/test_referral_analytics uv run pytest
# После завершения тестов:
docker stop referral-auth-test-db
```
