# Реферальные коды

Авторизованный пользователь создаёт код через `POST /api/v1/referrals/codes`.
Тело запроса — JSON-объект; поля `expires_at` и `max_uses` необязательны.
`expires_at` должен содержать часовой пояс и указывать на будущее. `max_uses` —
положительное целое число. Владелец определяется по access-токену, а значение
кода генерируется сервером. Для создания кода без ограничений передайте `{}`.

`GET /api/v1/referrals/codes` возвращает только коды текущего пользователя,
включая неактивные и истёкшие. Результат содержит `items`, `limit`, `offset`;
параметры `limit` (от 1 до 100, по умолчанию 20) и `offset` задают страницу.
Записи упорядочены по времени создания и идентификатору по убыванию. Использование
смещения может давать сдвиги между страницами при одновременном добавлении кодов.

Регистрация переходов и применение ограничений при атрибуции будут реализованы
отдельно. На текущем этапе выдаётся код, а URL реферальной ссылки не формируется.

`GET /api/v1/referrals/codes/{id}` возвращает информацию о собственном коде.
`PATCH /api/v1/referrals/codes/{id}` изменяет только переданные настройки:
`is_active: false` отключает код, а `expires_at` и `max_uses` задают срок
и лимит с теми же ограничениями, что при создании. Значение `null` снимает
ограничение срока или лимита. Пустой запрос, включение кода и изменение его
значения или владельца запрещены. Чужой или отсутствующий код возвращает 404.
Параллельные изменения разных настроек сохраняются; при изменении одного поля
последним сохраняется значение последнего завершившегося обновления.

## Администрирование программ

Только администратор может создавать программы (`POST /api/v1/admin/referral-programs`),
получать их список (`GET /api/v1/admin/referral-programs`) и изменять настройки
(`PATCH /api/v1/admin/referral-programs/{id}`). Другим авторизованным ролям
возвращается 403. Список упорядочен по UUID и поддерживает параметры `limit`
(1–100, по умолчанию 20) и `offset` (по умолчанию 0).

Поля программы: `name`, `reward_type` (`fixed` или `percentage`), `reward_value`,
`currency`, `starts_at`, а также необязательные `max_reward`, `ends_at` и `is_active`.
Суммы задаются положительными десятичными числами с максимум двумя знаками после
запятой; процент не может превышать 100. Валюта задаётся тремя заглавными латинскими
буквами. Временные значения должны содержать часовой пояс, окончание должно быть
позже начала. Отсутствие `ends_at` или `max_reward` означает отсутствие ограничения.

При изменении можно передать только нужные поля; `null` снимает ограничение даты
окончания или максимального вознаграждения. Итоговая конфигурация проверяется
целиком внутри транзакции с блокировкой программы, поэтому параллельные изменения
не создают некорректное сочетание даты, типа и значения вознаграждения. Изменения
программы и выбор правил для конкретного начисления — разные операции: фиксация
исторических правил будет добавлена вместе с модулем вознаграждений.
